# 知音 H5 字体放大问题审查

## 总体结论

问题由 H5 的 `rpx` 转换基准与 430px 桌面手机壳不一致造成。外层宽度已限制为 430px，但根字号仍按整个浏览器视口计算，导致全部 `rpx` 字号、间距和控件被放大。现已在桌面壳层固定 430px 的换算基准，并保留真实手机端的动态换算。

## 步骤

1. 异常首页 — 严重
   - 截图：`01-oversized-home.png`
   - 观察：场景标题、卡片标题和主推荐内容被放大并出现省略；搜索区与卡片密度异常。
   - 影响：用户无法完整识别入口名称，视觉层级失真，部分操作信息被遮挡。

2. 修复后桌面首页 — 健康
   - 截图：`02-fixed-home.png`
   - 观察：430px 画布保持居中；字号、卡片尺寸、搜索区和底部导航恢复正常比例；文字完整显示。

3. 390 × 844 手机尺寸 — 健康
   - 截图：`03-mobile-390x844.png`
   - 观察：手机断点继续使用真实屏宽换算；页面宽度和文档滚动宽度一致，无横向溢出。

4. 播放页同步检查 — 健康
   - 截图：`05-player-desktop.png`
   - 观察：沉浸背景、标题、控制面板与队列均保持在 430px 画布内，字号与间距正常。

## 最高优先级发现

- P1 已修复：桌面端 `rpx` 按外部浏览器宽度计算，造成全局 UI 放大和文本截断。
- P2 已修复：同一错误会影响首页之外的播放页和其他使用 `rpx` 的页面。

## 无障碍风险

- 修复前的大字号并不是可控的文字缩放，而是整体布局失配，导致文本截断和操作入口信息缺失。
- 修复后保留了既有移动端字号和触控目标；本次仅验证可见布局，未宣称完成键盘、读屏器或完整 WCAG 合规测试。

## 验证

- 桌面视口：根字号 18.3467px，应用宽度 430px。
- 手机视口：390 × 844，根字号 16.64px，应用宽度约 390px。
- 无横向溢出。
- 全新浏览器页无控制台错误。
- `npm.cmd run typecheck` 通过。
- `npm.cmd test`：21/21 通过。
